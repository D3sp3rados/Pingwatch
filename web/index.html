Standorte (Agenten)

☁️ UniFi-Cloud (ohne Agent)

UniFi-Konsolen ohne Agent vor Ort überwachen: PingWacht fragt die Konsole über die UniFi-Cloud von Ubiquiti ab – Geräte, Status, Laufzeit und Auslastung wie mit Agent. Ein Key gilt für alle Konsolen Ihres UniFi-Kontos.

So bekommen Sie den Key
  1. unifi.ui.com öffnen und mit dem UniFi-Konto anmelden, dem die Konsolen gehören.
  2. Links „API“ (Site Manager API) bzw. Profil → API Keys → „Create API Key“.
  3. Key kopieren (wird nur einmal angezeigt) und hier einfügen.
  4. Dann „+ UniFi-Cloud-Standort“ anlegen oder bei einem Standort „UniFi-Livestatus“ → Quelle „UniFi-Cloud“ wählen.
Voraussetzung: Konsole ab Firmware 5.0.3, UniFi Network ab 9.3. Der Key wird nur auf dem Server gespeichert und nie wieder angezeigt.
So kommt ein Standort dazu (lokale IPs pingen)
  1. Standort anlegen, dann agent.json und Windows-Agent herunterladen.
  2. Beide Dateien in denselben Ordner legen (z. B. C:\PingWacht) und pingwatch-agent.exe starten.
  3. Der Agent erscheint als Symbol im Infobereich der Taskleiste und startet ab jetzt automatisch mit Windows.
  4. Hosts mit diesem Standort anlegen – der Agent übernimmt sie innerhalb weniger Sekunden.
Fällt das Internet am Standort aus, puffert der Agent die Messwerte und schickt sie nach. Für einen Raspberry Pi gibt es den Linux-Agent (pingwatch-agent-linux-arm64 agent -config agent.json).

Wartungsfenster

Während einer Wartung gibt es keine Alarme, und Ausfälle zählen nicht in die Verfügbarkeit (Monatsbericht).

Testphase: PingWacht kann auf Windows- und Linux-Rechnern Updates suchen und installieren, bei Bedarf neu starten und Scripts aus der Script-Bibliothek ausführen – sofort oder per Plan. Frei eingetippte Befehle gibt es nicht.
Voraussetzungen: am Standort unter 💻 Rechner-Überwachung „Updates und Neustarts erlauben“ und die Zwei-Faktor-Anmeldung. Auf einem einzelnen Rechner abschaltbar mit "noActions": true in dessen agent.json. Während Updates mit Neustart sind Meldungen der Rechner 2 Stunden stumm.

Script-Bibliothek

PowerShell und cmd laufen unter Windows, bash und sh unter Linux/macOS – als Dienst-Benutzer des Agenten (Windows: SYSTEM, Linux: root). Als Prüfung markierte Scripts melden sich bei Exit-Code ≠ 0 (und wieder, wenn sie erneut erfolgreich sind) – z. B. alle 5 Minuten per Plan.

Abhängigkeiten aus der Netzkarte

Von der Zentrale aus wird der Weg zu jedem überwachten Host verfolgt. Jeder Host „hängt ab“ vom nächsten überwachten Host auf dem Weg dorthin (z. B. Kunde → Sektor → Mast). Fällt der übergeordnete aus, gibt es für die dahinter keine eigene Meldung. Pausierte Hosts werden übersprungen.
Orte

Neuen Ort oder Ortsteil anlegen (z. B. „Rickenbach“, „Egg“): Geräte auf der Karte mit Strg + Ziehen markieren (oder hier bei einem Ort „Auswählen“ und mit Strg + Klick anpassen), dann rechts „Ort setzen“ und den neuen Namen eingeben. Umbenennen auf einen vorhandenen Namen legt Orte zusammen.
Traffic per SNMP

Der Agent der Erreichbarkeitsprüfung fragt alle 5 Minuten die Schnittstellenzähler der Geräte ab (SNMP v2c, nur lesend) und speichert daraus den Traffic je Schnittstelle (Ø und Spitze je Stunde, 90 Tage). Auf den Geräten muss SNMP eingeschaltet und die Adresse des Agenten erlaubt sein.
